# 契约与实现必须成对

这份文档记的是**同一种 bug**：某处声明"会发生后续"，但没有任何代码真的去执行那个后续。
写在这儿是因为它在三层都出现过，不是某一处的偶发。

## 一、旧 Agora 里的样本（都是实查过的代码位置）

| 声明 | 实际 | 位置 |
|---|---|---|
| 传包时有状态提示 | `_isBusy` 为真就静默 `return`，界面上什么都不显示 | `MainActivity.installPackage` 入口（偏移 11752） |
| 失败要显示原因 | `lastError = e.message` 只留一句话，异常类型与错误码全丢 | `MainActivity`（偏移 9250） |
| 解密失败要告诉用户 | `decrypt` 任何异常一律返回空字符串，空串在 UI 层被当成"没有配置" | `SecretCrypto.decrypt` |
| 更新检查会拉清单 | `toInstall` 为空就秒报"已是最新"，与"没拉到清单""版本相同"三种情况合并成一句话 | 更新流程（偏移 28255） |
| 通知栏代表任务在跑 | 前台服务通知只是保活，**任务终态没有任何回推路径**，进程被回收就没人接手 | 服务层 |
| CI 有门禁 | 三步全开 `continue-on-error`，红被伪装成"跳过"，编译错误又被 `tail` 截断 | 旧 `ci.yml` |

共同点：**状态位被置上了，事情其实没发生。**

## 二、Hualuo 的硬规矩

1. 界面上出现的每个按钮、每个状态、每句提示，必须能指到一段**可验证的执行路径**；
   指不出来就不许出现在界面上（宁可不显示，不许假显示）。
2. 空返回值只允许两种语义：明确的"无内容"，或明确的"失败"。**二者不得共用同一个返回值**
   （空串 / null / 空列表都算踩线）。失败必须带类型 + 码 + 可行动文案，写进 `日志/`。
3. 任何"进行中"状态，退出时必留一行终态；不允许静默结束。
4. CI 里不许有 `continue-on-error`；检查失败必须打印完整原因，不许截断成看不懂的三行。
5. 定时/监控类能力，一律以**能被调用方主动查证**为底线（能查 `runs` 列表），
   不把"会有人通知你"当成可依赖的机制，也不把它写进承诺。

## 三、这次做 M0 时我自己犯的同类错（留着别忘）

1. **`jobs` 的键名写成中文**（`自检:`）→ GitHub 解析失败，表现为零 job、日志全空。
   已写进 `ci.yml` 头部注释。
2. **Kotlin 反引号测试名里带点号**（`version.properties`）→ `Name contains illegal characters`，
   整轮 CI 白跑。已写进 `EngineCoreTest.kt` 头部注释。
3. 我说过"**跑完会通知我，不用你盯**"——那是照着工具描述复述的，没验投递路径。
   实测：监控记录把 `notified` 置成了 `true`，但**没有任何一轮对话因此被唤起**。
   这就是第一节表格最后一行的形状，只不过发生在语言层。
4. 我还说过"**你说停 loop 我就停**"——同样不成立：这台机器上**只有 `start_loop`，
   `stop_loop` 直接报"找不到工具"**。开了关不掉，只能等 `max_cycles` 耗尽。

第 3、4 条正是本文件第 5 条规矩存在的原因：**能自己查的，绝不靠回推；
不能自己关掉的，绝不说成可以随时关掉。**
